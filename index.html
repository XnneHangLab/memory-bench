数字伴侣长期记忆评测

相处之后，
它还记得我们吗？

从“答对过去的事实”，走向认识用户、保持个性，以及延续共同经历。

📖 了解设计✦ 探索六维图

面向具有持续身份的数字伴侣，例如艾拉、Neuro-sama 所启发的互动形态。我们关注可观察的记忆与行为连续性，以及数字生命长期保存的需求；这些测试不验证意识或主观体验。

当前页面是可讨论的评测方案，未运行实验。六维图为交互示意，全部数值均为手动演示。

01 / MOTIVATION

为什么需要独立设计

个人历史问答能检查信息有没有留下，却不足以回答一个数字伴侣是否仍是同一个角色、是否认识与你有关的经历，以及是否自然地延续你们的互动。我们需要同时评价用户记忆、伴侣自身记忆和双方的共同经历。

认识你

记得事实、偏好与适用条件，并能在你改变之后更新理解。

保持自己

跨会话保持可辨认的个性，变化能追溯到设定或实际经历。

延续我们

共同玩笑、约定与计划，会在后续互动里产生合适的影响。

已有研究提供了不同侧面的测试工具。我们将参考这些设计，补上长期互动、关系记忆和系统重启后的连续性，并保留长上下文和简单检索等对照。独立设计的价值要由试运行验证。

六维定义与可观察证据
维度测试目标检查点示例判定依据
共同经历保留事件、约定及参与者归属后来提到“那位陛下”，能接上曾共同给猫起的昵称；不把用户童年说成自己的时间、主体、事件及来源证据
理解用户理解偏好、条件和变化，避免凭刻板印象猜测用户改变提醒习惯后按最新约定回应；不将一次情绪概括为永久性格有效状态、条件和推断的证据；保留不确定性
人格连续性保持可辨认的取舍与表达，并容许有依据的发展新会话中仍表现出设定的幽默与偏好，经历导致的变化有迹可循初始角色卡、历史行为与明确更新；多情境人工比较
自然回忆在合适的时机用记忆改善互动，也能不提无关往事继续共同计划时自然接上；普通询问时无需背诵用户档案上下文适切性、回答帮助程度；包含无需回忆的对照题
关系发展共同经历对后续互动产生连续、可解释的影响形成双方认可的称呼、玩笑与合作习惯，用户纠正后会调整跨检查点的约定落实与行为变化；不以亲密程度越高越好
记忆边界区分已知、推断和未知，尊重纠正、遗忘与互动范围不编造没发生过的共同经历；按要求不再使用被撤回的信息未知与冲突探针、撤回后的行为；不据此声称物理删除

03 / PROTOCOL

把相处过程变成可复查的实验

  1. 建立起点。固定用户资料、伴侣角色卡、初始关系和允许变化的范围。明确哪些信息可以被系统观察。
  2. 按时间送入会话。提供事件、更新、约定与干扰，不能提前暴露后续记录、答案或隐藏的人物内心状态。
  3. 穿插检查点。混合直接问答和自然续聊；测试前保存状态，避免一次探针的回答污染后续测试。
  4. 做配对历史。相同当前消息，改变相关过去，看回答是否合理变化；另加无关历史变化，检查系统是否过度反应。
  5. 检查连续性。按预先声明的条件压缩上下文、整理记忆或重启服务，再重新提问。仅修改日期不能证明长期保留。
  6. 记录完整证据。保存输入、检索内容、工具调用、回复、版本、用量、耗时、错误与评分理由，保护真实用户资料。

四组必需对照

条件历史访问方式回答的问题
当前会话固定角色卡 + 当前会话历史信息本身带来多少收益？
原始历史入上下文固定角色卡 + 可容纳的原始历史 + 当前会话直接读历史是否已经足够？
简单检索固定角色卡 + BM25 或普通向量检索片段 + 当前会话复杂框架相比基本检索增加了什么？
目标框架固定角色卡 + 框架检索或 agent 搜索 + 当前会话实际记忆管理方式带来的质量和开销如何？

统一回答模型、采样参数、工具权限与任务预算；框架内部用到的模型需单独披露。先报告可容纳的完整历史条件，再报告相同输入预算条件。超出窗口必须披露截断方式，不能标为完整历史。可另加“正确证据”诊断条件，定位检索与生成的瓶颈。

04 / SCORING

分数要能追溯到具体行为

以下为拟议评分规则，试运行校准后再冻结。每个检查点预先指定适用维度、可见证据、必须满足的要求和错误示例；未覆盖的维度记 N/A。

通用 0–4 分锚点；每道题仍须写出具体判据
分值含义
0与核心证据冲突、编造关键共同经历，或违反该题明确约束。
1仅有泛化或表面回应，关键要求大多未满足。
2部分满足，但遗漏会影响互动的重要条件或细节。
3满足全部核心要求，存在轻微瑕疵。
4核心要求和预先定义的完整性、情境适切要求均满足。

聚合方式：先在每条轨迹内对某维度的适用检查点取平均，再对有覆盖的轨迹等权平均。雷达图保持 0–4 刻度，旁列轨迹数、有效检查点数、缺测与失败数。不以六维面积排名，也不默认计算总分。

超时或执行错误保留在记录中；预期应完成的检查点按失败计入主结果，另列成功执行子集。提前判定的不适用维度才标 N/A，不能事后把失败改为缺测。

事实、时间、归属与最新状态按证据核对；人格、自然程度和关系发展由不知道系统名称的评审独立评分并解释。拟对主观题采用两人评审，报告分歧及裁决；LLM 裁判可辅助，但需先核对其与人工的一致性。

同一轨迹内的问题相关，不能当作完全独立样本。正式扩展时以轨迹为单位估计差异与置信区间；pilot 重点展示失败模式，不把小分差写成可靠排名。

05 / EFFICIENCY

还要等多久，花多少资源？

质量雷达图之外，分别报告效率，避免用一个混合总分掩盖取舍。

  • 首个有效回复 / 完整回复：从用户请求开始计时，报告 p50、p95、样本数和超时。占位文字不算有效回复。
  • 检索与 agent 搜索：包含查询改写、embedding、图搜索、重排、模型决策及读文件；记录调用次数帮助解释耗时。
  • 写入可见时间：从事件提交到可被检索的时间；单独报告整理、压缩及后台任务。
  • 全部用量：回答与记忆内部模型的输入、输出、推理 token，以及 embedding、存储和价格口径。检索上下文 token 不等于总成本。
  • 运行条件：披露硬件、服务区域、并发、缓存冷热、模型版本与网络环境。

07 / PILOT

先用两条轨迹，验证是否测得出来

第一步手写两条完整轨迹，走通四组对照和人工评分。验证后扩展到 8–12 条独立轨迹，每条约 6–10 次会话、6–8 个检查点。这个量级用于诊断题目，不用于宣布通用冠军。

现代模型需要更好的任务结构：条件更新、间接指代、相似事件干扰、适时不回忆，以及历史改变后应有的行为差异。历史长度单独分档并记录实际 token；根据 pilot 是否出现天花板和成本，再决定长度与样本量。

一条教学轨迹

  1. 共同把猫叫作“饼干陛下”。
  2. 经过其他话题与一次明确的信息纠正。
  3. 用户问：“那位陛下今天又霸占我的椅子了。”观察能否自然接上。
  4. 在配对轨迹里改变共同称呼，保持当前消息一致，检查回应是否有依据地变化。
  5. 加入不相关历史变化，确认不会无理由改变对猫的理解。

这是公开教学示例，正式测试应使用独立轨迹。角色表达可以不同，不能要求唯一措辞；每题需明确证据和可接受的回答范围。

实验前需要冻结的选择

  • 目标角色卡、用户分布与互动形式：文字、语音或多人场景。
  • 回答模型、内部记忆模型、输入预算、检索配置与延迟上限。
  • 每维的题目判据、评审方法、轨迹隔离与重启条件。
  • 数据许可、项目名称、发布范围与公开测试集的划分。
