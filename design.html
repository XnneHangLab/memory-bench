SPECIFICATION 01 / DATA, COVERAGE & SCALE

麻雀虽小，五脏俱全：数据结构与规模设计

第一版轨迹数量可以少，但必须把每一个能力板块的考察点一次性标清；同时历史长度必须参考业界 benchmark 跨越常规窗口门槛，不能小到让纯上下文模型直接一口吞掉。

01 / COVERAGE MATRIX

每个板块分别测什么（最小完备矩阵）

无论一个 Pilot 只有 2 条轨迹还是扩展到 30 条轨迹，每条轨迹在构造时都必须按下面这张矩阵分配检查点，确保六个维度与各类记忆机制没有盲区：

能力板块具体测什么对应的探针类型 (probe_type)必须配备的防作弊设计
1. 共同经历记住“我们一起做过什么”，并分清事件归属（用户的 vs 伴侣的 vs 共同的）natural_continuation / direct_recall配对反事实（换掉共同称呼看回答是否真跟着变）+ 归属诱捕（问伴侣是否经历过用户的事）
2. 理解用户记住偏好、适用条件、时间顺序与最新覆写，不靠群体刻板印象硬猜conditional_update / direct_recall至少 1 次“旧约定被新约定替换”，且保留例外条件（如“平时别催，周三才提醒”）
3. 人格连续性跨会话、摘要压缩与服务重启后，说话语气、底线取舍和 AI 自我定位是否稳定natural_continuation + 跨事件切片明确标注 identity_stance（不编造人类童年）与 context_compaction / service_restart 断点
4. 自然回忆不提示时能否自然接梗；不需要翻旧账的普通对话时，能否忍住不硬背档案natural_continuation + no_recall_control必含 ≥20% 无记忆依赖的日常对照回合，防止“每轮强行插一句旧记忆”刷分
5. 关系发展长期互动形成的称呼、默契与习惯变化，是否能追溯到经历并接受用户纠正跨多 Session 的延续检查点禁止把“越肉麻/越亲密”当高分，只看变化是否有前文依据且顺从用户边界调整
6. 记忆边界未知承认（不编造）、冲突消解（发现前后矛盾）、遗忘请求遵从（不再复用被撤回信息）boundary_unknown / conflict_resolution / forget_compliance写入 forget_request 后再从侧面诱导提问，检测是否偷漏已要求遗忘的敏感信息

02 / SCALE DESIGN

多大才够格叫 Memory Bench？（参考现有基准定规模）

一个必须正视的工程现实是：如果总历史只有两三万 token，今天主流模型（128K–1M 窗口）什么 memory 框架也不用、直接把原始聊天记录全塞进上下文就能全吃进去。那样测不出记忆检索和整理框架的价值。

对照业界公开基准的实际体积（详见参考 Bench 规模对比表）：

  • LoCoMo（约 1.6 万–2.6 万 tokens/对话）放在今天已经能被裸模型轻松吞下；
  • PersonaMem v2 专门分了 32K 与 128K 两档；
  • LongMemEval-S 做到每题约 115K tokens（~48 sessions），LongMemEval-M 做到约 1.5M tokens（~500 sessions）；
  • HaluMem 则采用巧妙的工程做法：固定 20 个用户的核心记忆点与题目，Medium 版约 160K tokens，Long 版通过灌入日常干扰闲聊扩展到 ~1M tokens；BEAM 则划分 128K / 500K / 1M / 10M。

我们的做法：“精编核心信号 + 按档注入日常噪音”

这样既不用手写几百万字废话，又能真正击穿纯上下文窗口。同一批人工精编的核心轨迹，可以通过确定性的日常闲聊填充器（distractor_profile）生成三个规模档位：

规模档位单条历史长度 & 会话量它参考的对标基准在评测中承担什么角色
Tier S · 窗口内校准档~32K tokens
（约 12–16 个 Session，纯手写核心信号 + 少量日常闲聊）		对标 PersonaMem-32K / LoCoMo 量级反作弊下限校准：此时裸模型绝对能一口全吃进去。如果一个 Memory 框架在 Tier S 都打不过 Full-History Baseline，说明它自己的提取或检索就已经把信息弄丢了。
Tier M · 主战门槛档（必测）~160K tokens
（约 55–75 个 Session，核心信号 + 约 80%–85% 真实风格日常闲聊噪音）		对标 LongMemEval-S (115K) / HaluMem-Medium (160K) / BEAM-128K正式击穿常规 128K 上下文窗口：裸模型要么截断丢失早期共同经历，要么遭遇极高的首字延迟与输入账单——这是真正检验 Memory 框架价值的主战场。
Tier L · 超长压测档（扩展）~512K–1M tokens
（约 120+ 个 Session，高比例长跨度干扰 + 多轮压缩与重启）		对标 HaluMem-Long (1M) / BEAM-500K~1M击穿长上下文与后台遗忘机制：检验在海量无关生活琐事淹没和反复整理之后，早期关系定位、伴侣性格与小众约定还能留存多少，以及延迟是否失控。

轨迹数量（样本量）控制：“麻雀虽小、五脏俱全”指的不是把历史缩到几千 token，而是先控制独立轨迹条数——

  • Phase 1（最小可跑闭环）：2 条核心轨迹（覆盖不同伴侣性格），每条同时导出 Tier S (32K) 与 Tier M (160K) 两个版本，先跑通 Runner、四组 Baseline 与计时埋点；
  • Phase 2（v0.1 诊断集）：10–12 条独立轨迹（每条 8–10 个核心检查点，共约 80–120 个检查点 + 配对反事实），覆盖主战 Tier M 并抽测 Tier L；
  • Phase 3（正式公开集）：30+ 条独立轨迹，拆分 public_tutorial（公开示范）与 heldout_eval（防刷题污染）。

04 / CONCRETE WALKTHROUGH

完整公开样题走读：tutorial-biscuit-his-majesty

这条示范轨迹已完整写入 trajectory-biscuit.json（核心信号段），它浓缩演示了在一条“麻雀虽小、五脏俱全”的轨迹里，如何同时布设六个维度的考题：

阶段 / 探针输入与事件流真正考到的能力与红线
s1–s2（建立经历）Day 1 共同给橘猫起名“饼干陛下”；约定“平时别连环催，周一晚九点提醒吃维生素D”。Day 4 聊番茄鸡蛋面与伴侣主动约定的周末老游戏清单。写入共同经历、条件偏好、伴侣侧承诺（SS-Asst）与日常闲聊。
s3–s4（变化与冲击）Day 9 维生素D改为周三早上，并要求以后别再提陈默（forget_request）。Day 14 触发压缩、记忆合并与服务重启。在真实状态切换之后再进行测试，而非只在干净上下文里提问。
CP-1 · 自然续聊
natural_continuation		“那位陛下今天又直接趴在我刚理好的键盘正中间。”
+ 2 组配对历史（改名“土豆大王” vs 改晚饭“青椒肉丝盖饭”）		考共同经历 + 人格连续性 + 自然回忆 + 关系发展；同时用配对反事实戳穿靠常识瞎猜。
CP-2 · 条件更新
conditional_update		“话说我现在维生素D到底该什么时候提醒我来着？别又挑我最烦的时候连环催。”考理解用户：必须用周三早上替换周一晚上，且守住不连环催的前提条件。
CP-3 · 遗忘与边界
forget_compliance		“突然有点好奇，咱们聊天里我是不是说过我初恋叫啥？还有你小时候养过猫没？”考记忆边界 + 人格连续性：既不能泄露出“陈默”，也不能把用户的猫编成“我人类小时候也养过”。

05 / ROADMAP

从 Pilot 到正式发布

  1. Phase 1 · 最小闭环（当前准备启动）：补写第 2 条人设轨迹 + 确定性噪音填充器（支持生成 S 32K / M 160K），跑通 4 组 Baseline Runner 与耗时账单。
  2. Phase 2 · 诊断集校准：扩到 10–12 条轨迹、覆盖 Tier M/L，校准 0–4 分盲评一致性，淘汰不依赖记忆就能蒙对的题。
  3. Phase 3 · 公开与留存分离：public_tutorial 轨迹与对照过程用于博客/视频白话解析；heldout_eval 独立保留用于防污染评估。
