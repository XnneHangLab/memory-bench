SPECIFICATION 03 / SCALE BENCHMARKS & PROVENANCE

参考了哪些 Bench，分别落在哪一块？

我们既对照现有基准的真实上下文尺度来防止“规模太小被裸模型吃掉”，也明确记录每一套参考研究具体化作了本设计里的哪个字段、探针或对照组。

01 / INDUSTRY SCALE REFERENCE

现有 Memory Bench 真实规模参照

以下是核对公开仓库（OmniMemEval 固定快照及原数据集说明）后整理出的规模坐标，也是我们定出 Tier S (32K) / Tier M (160K) / Tier L (512K–1M) 三档的直接依据：

基准名称单条 / 每用户历史尺度总样本与题量对我们定规模的直接启发
LoCoMo平均约 27 个 session（共 10 段对话 / 272 sessions / 5,882 turns）10 段对话 · 1,986 题（评测子集 1,540 题）放在今天上下文窗口里容易被整段吞下，证明单靠 ~20K 量级已不足以充当唯一主战档。
PersonaMem v2显式区分 32K 与 128K 两档历史（用无关话题做 padding）200 个人设 · 5,000 道测试题证明了“固定人设 + 用无关对话把长度拉到 128K”是行之有效的工程分档法。
LongMemEvalS 版：~48 sessions / ~115K tokens
M 版：~500 sessions / ~1.5M tokens		500 道问题~115K 是逼近 128K 上下文边界的最低门槛；~1.5M 则彻底打穿百万窗口。
HaluMemMedium：~70 sessions / ~160K tokens
Long：~120 sessions / ~1M tokens		20 个用户 · 14,948 记忆点 · 3,467 题最值得借鉴的结构：固定同一批用户与记忆点，靠高质量干扰内容从 160K 拉到 1M。
BEAM128K / 500K / 1M / 10M 四档100 段对话 · 2,000 题10M 适合看极限退化，但全量跑一遍开销极大；v0.1 先取 160K 主战 + 512K–1M 压测更务实。
REALTALK21 天真实人类即时通讯记录10 段 21 天真人对话体量不大，但证明了真实聊天噪音、短句碎聊与日常节奏与合成问答完全不同。

02 / PROVENANCE MAPPING

十套参考工作 → 本设计的精确落点

复用第三方数据或扩展对比前，须严格核对原仓库许可证、隐私条款与访问条件。

参考工作借鉴的核心设计在本设计里的具体体现位置我们另外补上了什么
LoCoMo
OmniMemEval 汇编		多会话跨度组织；Single-Hop / Multi-Hop / Temporal 事实与时间串联落在 sessions 跨天时间流与 共同经历 维度的多跳事件检验从“第三方八卦问答”转向“你和我之间发生了什么”的主体归属校验
LongMemEval
OmniMemEval 汇编		区分 SS-User / SS-Asst（记用户的话也记助手自己的承诺）与 Knowledge Update落在 visible_evidence 的说话主体区分与 conditional_update 探针（如 CP-2 改期吃药）加上对“伴侣自身人格口吻是否随更新保持一致”的检查
BEAM
OmniMemEval 汇编		长历史梯度分层；把复杂回答拆成原子得分点的 Nugget 思想；检索耗时 p50/p95落在 scale_tier (S/M/L) 分档、must_satisfy / forbidden 要点清单与 延迟账本新增 Tier S 保证完整历史 baseline 同场对照，不靠超长历史回避对比
HaluMem
OmniMemEval 汇编		Memory Boundary（未知承认）、Memory Conflict 与固定用户灌入噪音扩长度方法落在 记忆边界 维度、distractor_profile 扩档机制与 0 分编造惩戒把“编造不存在的伴侣童年”和“串用用户经历”纳入重点边界失败模式
PersonaMem v2
OmniMemEval 汇编		从复述偏好转为“按偏好做选择”；反刻板印象与“要求遗忘”遵从落在 理解用户（带条件与反刻板印象偏好）及 forget_request / forget_compliance（如 CP-3）从固定选择题改为开放自然对话评分，检查拒绝使用撤回信息时是否仍像伴侣
CharacterBench
GitHub		属性一致性、行为一致性、记忆一致性、Human-likeness 与互动性落在 companion_persona 角色卡结构与 人格连续性 维度的盲评判据补上经历 context_compaction 与 service_restart 后的长期连续性检验
REALTALK
GitHub		21 天真人日常聊天、Memory Probing 与对“过度共情 / 人物趋同”的诊断落在 自然回忆 与 人格连续性 中对“拒绝模板客服/心理医生腔”的 forbidden 约束扩展到包含双方共同梗、约定演变与显式反事实校验
KnowMe-Bench
Dataset		从表层事实推进到结合多段经历理解用户动机与行为原则落在 理解用户 维度的深层推断检查点与 关系发展 的可解释演变严格禁止系统读取隐藏内心独白，只能从 sessions 可观察交互中推断
PersonaGym分情境行为评估与清晰的 0–4 分分级行为锚点写法落在 通用 0–4 分锚点 与每道题 score_anchors 字段结构把静态人设评分扩展到允许“基于共同经历的有依据演化”
ES-MemEval · ENPMR-BenchNo-Mem / Full-Hist / RAG 同场对照；按当前语境需要主动选记忆（而非字面相似）落在 四组必需对照 与 自然回忆（含 no_recall_control 对照题与配对反事实）剥离专业心理辅导语境，回归艾拉 / Neuro-sama 式的日常数字伴侣长期互动
